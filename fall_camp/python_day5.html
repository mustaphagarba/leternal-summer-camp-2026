🧱 Classes: Blueprints for Objects

A class is a blueprint. An object is a real thing built from that blueprint.

📐 Blueprint: Planet
(name, distance, radius, color)
⬇️ build one ⬇️
🌍 earth 🔴 mars 🟠 venus
🏠 The plan for a house isn't a house. Build from the plan, and you get a real one!

📝 Defining the Planet Class

class Planet: def __init__(self, name, distance): self.name = name self.distance = distance
  • class Planet: starts the blueprint (capital P!)
  • __init__ runs automatically when a planet is built
  • self means "this particular planet"

🏗️ Building Planet Objects

earth = Planet("Earth", 10) mars = Planet("Mars", 13) print(earth.name) print(mars.distance)
Earth
13
✨ earth.name reads like English: "earth's name." Each object keeps its OWN facts.

⚙️ Methods: Functions Inside a Class

class Planet: def __init__(self, name, distance): self.name = name self.distance = distance def describe(self): print(f"{self.name} orbits {self.distance} units from the Sun") earth = Planet("Earth", 10) earth.describe()
Earth orbits 10 units from the Sun
🎯 A method is just a function (Day 3!) that belongs to the class and can read the object's own facts through self.

🌐 Bringing the Planet Into 3D

Now the blueprint also builds a glowing... well, a 3D sphere for each planet:

self.body = sphere( pos=vector(distance, 0, 0), radius=radius, color=planet_color )
📍 pos=vector(distance, 0, 0) puts the planet out along the x-axis, that many units from the Sun at the center. We save the sphere as self.body so the planet remembers it!

📄 File 1: planet.py

planet.py
from vpython import * class Planet: def __init__(self, name, distance, radius, planet_color): self.name = name self.distance = distance self.radius = radius self.body = sphere(pos=vector(distance, 0, 0), radius=radius, color=planet_color) def describe(self): print(f"{self.name} orbits {self.distance} units from the Sun")

📄 File 2: main.py

main.py
from vpython import * from planet import Planet scene.background = color.black sun = sphere(pos=vector(0, 0, 0), radius=2, color=color.yellow, emissive=True) earth = Planet("Earth", 10, 0.5, color.blue) mars = Planet("Mars", 13, 0.4, color.red) while True: rate(60)
🔌 from planet import Planet pulls the class in from planet.py. Both files must live in the SAME folder!

⚠️ Why "planet_color" and Not "color"?

VPython already uses the word color (as in color.blue). If our parameter is also called color, the two get tangled up inside the class!

def __init__(self, name, distance, radius, planet_color): ... color=planet_color # left side: VPython's setting # right side: OUR parameter
🕵️ Picking names that don't clash with other tools is a real programmer skill. When in doubt, add a descriptive prefix!

🐛 Import Trouble?

  • Both files must be in the SAME folder
  • The file is planet.py (lowercase), the class is Planet (capital P)
  • Run main.py, not planet.py!
  • "ModuleNotFoundError" usually means a typo in the filename or import line

📏 Heads Up: Not to Scale!

  • Real distances: Earth is 150 million km from the Sun, Neptune is about 4,500 million km
  • To fit on your screen, we squash the distances (Earth = 10, Mars = 13)
  • Drawn truly to scale, the planets would be invisible specks!
🌌 Real astronomers make "not to scale" diagrams too. Space is mostly empty, and honest models tell you what they changed!

🧠 Why Bother With Classes?

  • All of a planet's facts live in ONE tidy object
  • New planets are one line each
  • Next week we'll add an orbit() method, and every planet will know how to orbit itself!

🐛 Common Class Bugs

  • Forgot self. in front of a name inside the class
  • Wrote _init_ instead of __init__ (two underscores each side!)
  • "missing required positional argument" → you gave the planet too few facts
  • A planet hiding inside the Sun → its distance is too small
🕵️ Read the LAST line of the error message first. It usually names the exact problem!
